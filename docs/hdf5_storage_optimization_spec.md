# Рекомендации по оптимизации объема хранения данных Монте-Карло в HDF5

## 1. Введение и цели оптимизации
При моделировании реалистичных ОФЭКТ-исследований (60–120 ракурсов по $10^5 - 10^6$ актов взаимодействия на файл) несжатые сырые массивы быстро достигают десятков гигабайт. 

Данный документ описывает правила оптимизации схемы хранения данных в HDF5, позволяющие **сократить объем файлов в 4.7–8 раз** без потери физической точности и информативности.

---

## 2. Исключение избыточных локальных систем координат (`local_position` / `local_direction`)

### Проблема:
Хранение независимых массивов `local_position` $(N, 3)$ и `local_direction` $(N, 3)$ дублирует `global_position` и `global_direction`, расходуя **$48\text{ байт}$ на каждое событие** ($24\text{ байта}$ в `float32`).

### Решение:
1. Массивы `local_position` и `local_direction` исключаются из наборов данных `interactions/Detector_N`.
2. В группу `metadata/gantry` (или в атрибуты группы детектора) записывается единая матрица аффинной трансформации $4 \times 4$ для каждого детектора:
   $$P = \begin{bmatrix} R & \vec{T} \\ \mathbf{0}^T & 1 \end{bmatrix}$$
   где $R$ — ортогональная матрица поворота $3 \times 3$, $\vec{T}$ — вектор мирового центра детектора $[T_x, T_y, T_z]$.

### Восстановление в коде постобработки (`nmspect.io.SimulationDataExtractor`):
Обратное преобразование из мировой системы в локальную систему кристалла выполняется мгновенно векторной операцией NumPy в `SimulationDataExtractor.extract_data`:
$$\vec{r}_{\text{local}} = (\vec{r}_{\text{global}} - \vec{T}) \cdot R$$
$$\vec{d}_{\text{local}} = \vec{d}_{\text{global}} \cdot R$$

```python
# Быстрое векторное вычисление для всего массива актов:
rotation = pose_matrix[:3, :3]
translation = pose_matrix[:3, 3]

local_position = (global_position - translation) @ rotation
local_direction = global_direction @ rotation
```

## 3. Кодирование категориальных строк в компактные целочисленные типы (`uint8`)

### 3.1. `process_name` $\longrightarrow$ `process_code` (`uint8`)
* **Текущее состояние:** тип `|S30` (фиксированная строка **30 байт** на каждое событие).
* **Оптимизация:** сохранять `process_code` типа **`uint8`** (**1 байт**, экономия в 30 раз!).
* **Таблица соответствия:** записывается однократно в атрибут датасета `attrs["mapping"]`:
  * `0`: `"Emission"` (испускание)
  * `1`: `"ComptonScattering"` (комптоновское рассеяние)
  * `2`: `"RayleighScattering"` (рэлеевское рассеяние)
  * `3`: `"PhotoElectric"` (фотоэффект)
  * `4`: `"eIoni"` (ионизация электроном отдачи)
  * `5`: `"eBrem"` (тормозное излучение)

### 3.2. `species` $\longrightarrow$ `species_code` (`uint8`)
* **Текущее состояние:** тип `|S30` (**30 байт** на событие).
* **Оптимизация:** сохранять `species_code` типа **`uint8`** (**1 байт**).
  * `1`: `"gamma"`
  * `2`: `"e-"`
  * `3`: `"e+"`
  * `4`: `"opticalphoton"`

### 3.3. `material_id` и `volume_id` $\longrightarrow$ `uint8` / `uint16`
* **Текущее состояние:** `int64` (**8 байт** на событие).
* **Оптимизация:** в геометрии гамма-камеры число уникальных объемов и материалов не превышает 255. Использование **`uint8`** (1 байт) дает экономию **7 байт** на каждое поле.

---

## 4. Исключение предрассчитанных углов (`scattering_angles`)
* Полярный угол рассеяния $\theta$ между входящим $\vec{d}_{\text{in}}$ и выходящим $\vec{d}_{\text{out}}$ квантом тривиально вычисляется как:
  $$\cos \theta = \vec{d}_{\text{in}} \cdot \vec{d}_{\text{out}}$$
* Исключение датасета `scattering_angles` $(N, 2)$ экономит **16 байт** на каждый акт.

---

## 5. Опциональный выбор разрядности с плавающей точкой: `float32` vs `float64`

Выбор между одинарной (`float32`) и двойной (`float64`) точностью должен быть **настраиваемой опцией симулятора**:

```yaml
# Конфигурация экспорта симулятора:
storage:
  floating_point_precision: "float32"   # Варианты: "float32" (по умолчанию) или "float64"
```

В метаданных файла HDF5 фиксируется режим:
`metadata/simulation/precision_mode = "single"` (или `"double"`).

### Обоснование выбора точности:
1. **Режим `float32` (Рекомендуется по умолчанию для ОФЭКТ):**
   * Точность мантиссы: 24 бита ($\approx 7$ значащих десятичных цифр).
   * При габаритах сканера $500\text{ мм}$ шаг точности составляет $\Delta r \approx 0.00003\text{ мм}$ ($30\text{ нм}$).
   * Собственное пространственное разрешение кристалла $\text{NaI(Tl)}$ составляет $4.0\text{ мм}$ (в 100 000 раз грубее).
   * Вес всех вещественных датасетов сокращается **ровно в 2 раза**.
2. **Режим `float64` (Опциональный для прецизионных задач):**
   * Применяется при субмикронном трекинге через микроструктурированные коллиматоры, прецизионном расчете многократного рассеяния в наноструктурах или при специальных требованиях метрологии.

## 7. Рекомендации по сжатию контейнера HDF5 (Chunking & Compression)
Для датасетов событий объемом более 10 000 строк рекомендуется включить чанкование и алгоритмическое сжатие:
* `chunks=(16384,)` или `chunks=(8192, 3)` — обеспечивает оптимальный размер буфера ввода-вывода;
* `compression="gzip", compression_opts=4` (или `compression="lzf"`) — быстрый алгоритм, который за счет однородных массивов `uint8` и `float32` дает дополнительное сжатие **еще в 2–3 раза** практически без задержки при чтении.
