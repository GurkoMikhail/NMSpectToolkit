# Спецификация метаданных моделирования Монте-Карло (Физический транспорт частиц)

## 1. Концепция и границы ответственности
Данная спецификация описывает структуру данных, формируемую **кодом моделирования Монте-Карло** (Geant4 / Gate / внутренний трекер).

### Граница ответственности симуляции:
* **Включает:** Физический перенос и взаимодействия первичных и вторичных частиц в геометрии сцены (источник, фантом, коллиматор, воздух, кристалл детектора), а также кинематическое положение механических узлов гантри на момент экспозиции ракурса.
* **Исключает:** Электронные эффекты формирования сигнала, сцинтилляционное высвечивание, аппаратное размытие FWHM, биннинг в пиксели и выбор энергетических окон — эти параметры относятся к **системе детекции** ([`detection_system_parameters_spec.md`](detection_system_parameters_spec.md)) и варьируются на этапе постобработки в пакете `nmspect` (`SimulationDataExtractor`, `ScintillationProcessor`, `ProjectionBuilder`, `SpectrumProcessor`).

## 2. Структура HDF5-файла на выходе Монте-Карло

Каждый файл симуляции соответствует одной статической угловой позиции станины (или серии углов) и должен содержать следующие корневые группы:

```text
output_angle.hdf5
├── initial_states/       (начальные состояния рожденных квантов)
├── interactions/         (микроскопические акты взаимодействия)
│   ├── Detector_1/       (акты в объеме чувствительного кристалла 1)
│   ├── Detector_2/       (акты в объеме чувствительного кристалла 2)
│   └── Simulation_volume/(акты рассеяния в теле пациента/фантома)
└── metadata/             (паспорт геометрии, нуклида и кинематики)
    ├── gantry/           (углы поворота, орбита, мировая матрица позы)
    ├── geometry/         (физические габариты кристалла, коллиматор)
    ├── source/           (радионуклид, активность, модель фантома)
    └── simulation/       (метрология генератора, число первичных историй)
```

## 3. Описание датасетов физических взаимодействий

### 3.1. Группа `initial_states` (Генератор первичных частиц)
Содержит параметры родившихся радиоактивных распадов:

| Имя датасета | Размерность | Тип данных | Единицы (`hepunits`) | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `particle_ID` | `(N_init,)` | `uint64` | — | Уникальный глобальный идентификатор кванта |
| `emission_position` | `(N_init, 3)` | `float64` | `mm` | 3D-координаты точки рождения в фантоме $[x, y, z]$ |
| `emission_direction`| `(N_init, 3)` | `float64` | — | Единичный вектор направления вылета кванта |
| `emission_energy` | `(N_init,)` | `float64` | `MeV` (или `keV`) | Начальная кинетическая энергия гамма-кванта при распаде |
| `emission_time` | `(N_init,)` | `float64` | `ns` (или `s`) | Физический момент времени распада ядра от старта симуляции |

### 3.2. Группы детекторов `interactions/Detector_1`, `Detector_2`
Содержит акты взаимодействия квантов внутри чувствительного объема детектора (размерность $N_{\text{acts}}$):

| Имя датасета | Размерность | Тип данных | Единицы (`hepunits`) | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `particle_ID` | `(N,)` | `uint64` | — | Ссылка на квант из `initial_states` |
| `global_position` | `(N, 3)` | `float32` *(или `float64`)* | `mm` | Абсолютные координаты взаимодействия в системе мира |
| `global_direction`| `(N, 3)` | `float32` *(или `float64`)* | — | 3D-вектор направления импульса фотона в точке взаимодействия |
| `energy_deposit` | `(N,)` | `float32` *(или `float64`)* | `MeV` (или `keV`) | Истинная локально переданная энергия в данном микроакте |
| `distance_traveled`| `(N,)` | `float32` *(или `float64`)* | `mm` | Полный пройденный путь фотона от точки рождения |
| `process_code` | `(N,)` | `uint8` | — | Целочисленный код процесса (1: Compton, 2: Rayleigh, 3: PhotoElectric, 4: eIoni). Таблица в атрибутах. |
| `species_code` | `(N,)` | `uint8` | — | Код частицы (1: gamma, 2: e-, 3: e+). Таблица в атрибутах. |
| `Z` | `(N,)` | `int8` | — | Атомный номер ядра мишени ($Z=53$ для йода, $Z=82$ для свинца) |
| `material_id` | `(N,)` | `uint8` / `uint16` | — | Идентификатор материала объема |

> [!NOTE]
> 1. Поля `local_position` и `local_direction` исключены для экономии памяти; они рассчитываются на лету через `pose_matrix` детектора из `metadata/gantry`.
> 2. Разрядность чисел с плавающей точкой (`float32` vs `float64`) является **настраиваемой опцией симулятора** (по умолчанию `float32` для экономии памяти, `float64` — опционально для прецизионных расчетов).
> 3. Подробное обоснование и таблицы экономии памяти приведены в документе [`hdf5_storage_optimization_spec.md`](hdf5_storage_optimization_spec.md).

### 3.3. Группа среды `interactions/Simulation_volume`
Содержит акты рассеяния квантов в фантоме, воздухе и окружении до попадания в детектор. Формат полей полностью идентичен `interactions/Detector_1`.

## 4. Описание группы `metadata`

Данные метаданных позволяют конвертерам автоматически сформировать клинические заголовки **DICOM NM**, научный архив **NeXus** и 3D-сцену **VTK** без угадывания параметров.

### 4.1. Подгруппа `metadata/gantry` (Кинематика и ориентация)
* `gantry_angle` (`float64`, единицы `deg`): Угол поворота станины гантри (например, `0.0`, `3.0`, `6.0`).
* `orbit_radius` (`float64`, единицы `mm`): Расстояние от центра вращения (COR) до лицевой плоскости детектора (например, `250.0`).
* `rotation_direction` (`string`): Направление вращения (`"CW"` или `"CCW"`).
* `frame_duration` (`float64`, единицы `s`): Моделируемое физическое время экспозиции кадра (например, `30.0`).
* `angular_step` (`float64`, единицы `deg`): Шаг поворота гантри (например, `3.0`).
* `pose_matrix_detector_1` (`float64 [4, 4]`): Матрица аффинного преобразования (поворот + сдвиг) для детектора 1.
* `pose_matrix_detector_2` (`float64 [4, 4]`): Матрица аффинного преобразования для детектора 2.

### 4.2. Подгруппа `metadata/geometry` (Паспорт геометрии гамма-камеры)
* `crystal_dimensions` (`float64 [3]`, единицы `mm`): Физические размеры кристалла NaI(Tl) $[L_x, L_y, L_z]$ (например, `[537.6, 384.0, 9.525]`). Задает истинный **Field of View (FOV)** для исключения ошибок центровки при биннинге.
* `detector_heads_count` (`int32`): Количество детекторных головок (например, `2`).
* `collimator_type` (`string`): Тип каналов (`"Parallel Hole"` / `"LEHR"`).
* `collimator_hole_diameter` (`float64`, единицы `mm`): Диаметр каналов коллиматора (например, `1.1`).
* `collimator_hole_length` (`float64`, единицы `mm`): Длина каналов (например, `35.0`).
* `collimator_septa_thickness` (`float64`, единицы `mm`): Толщина свинцовых перегородок (например, `0.16`).

### 4.3. Подгруппа `metadata/source` (Источник и фантом)
* `radionuclide` (`string`): Название нуклида (`"161Tb"`, `"123I"`, `"99mTc"`).
* `half_life` (`float64`, единицы `s`): Период полураспада изотопа (например, `595296.0` для 161Tb).
* `simulated_activity` (`float64`, единицы `Bq`): Заданная начальная активность источника в Бк.
* `phantom_type` (`string`): Тип фантома (`"NEMA IEC Body Phantom"`).

### 4.4. Подгруппа `metadata/simulation` (Паспорт расчета)
* `code_name` (`string`): Название Монте-Карло кода.
* `code_version` (`string`): Версия движка моделирования.
* `physics_list` (`string`): Использованный физический конструктор Geant4 (`"emstandard_opt4"`).
* `simulated_histories` (`uint64`): Суммарное число смоделированных первичных квантов в данном файле.
* `random_seed` (`uint64`): Зерно ГСЧ для воспроизводимости.
